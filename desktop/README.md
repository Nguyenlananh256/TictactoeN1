# Caro Arena — C++ desktop

Native C++17 / Qt Widgets application. This version does not load the HTML page or require a browser, Node.js, or a web server. This replaces the former web implementation, which remains available in Git history.

## Features

- Notebook grid background, blue ink, red O marks, pale yellow settings card, hand-drawn board marks.
- English interface; no introductory slogans or footer text.
- 9×9 board, X plays first, at least five in a row wins (including blocked ends and overlines), full-board draw.
- Two-player local play, undo, restart confirmation, live move history, game clock, JSON export.
- Human vs AI / AI vs AI settings, separate algorithm selection for X and O, depth, candidate limit, exploration c and iterations.
- Native C++ AI adapter on a worker thread. Pause/resume, cancellation and stale-result protection.
- No AI algorithms are included. Missing providers are clearly indicated. Metrics are displayed only when available.
- Keyboard: Tab to the board, arrow keys to move the focus marker, Space/Enter to place a mark.
- Small windows use scrolling so controls remain accessible. This is a desktop layout rather than the mobile layout of the web version.

The same Patrick Hand font used by the web interface is bundled in Qt resources under the SIL Open Font License (`assets/OFL.txt`). It works offline. Segoe Print / other system fonts are fallbacks. No fonts are downloaded at runtime.

## Visual Studio 2026 (Windows)

Use **Desktop development with C++**, a Windows SDK, CMake 4.2 or newer, and a **Qt MSVC x64** package. Do not link the MinGW Qt libraries with the MSVC compiler.

From PowerShell at the `desktop` directory, set the Qt path for that terminal and generate the solution:

```powershell
$env:CARO_QT_MSVC = 'C:/Qt/6.8.3/msvc2022_64'
cmake --preset vs2026-x64
cmake --build --preset vs2026-release
ctest --preset vs2026-release
```

Replace the example Qt path with the installed MSVC package. Open `desktop/build-vs2026/CaroArena.slnx` in Visual Studio. Select **Release | x64** and start **CaroArena** with Ctrl+F5. CMake sets it as the startup project. Qt runtime DLLs and plugins are copied beside the executable after building; keep them with the app. The machine also needs the Microsoft C++ runtime, which is installed with Visual Studio.

Alternatively open the `desktop` folder in Visual Studio's CMake mode and choose the `vs2026-x64` preset. A local, ignored `CMakeUserPresets.json` can supply `CARO_QT_MSVC` without setting a system environment variable. If Visual Studio does not offer a compatible CMake version, generate the solution with an external CMake 4.2+ and open the generated solution (`.slnx` with current CMake).

## Open in Qt Creator (Windows)

1. Install Qt with a **Desktop Qt 6 MinGW 64-bit** kit, its matching MinGW compiler, CMake and Ninja. Qt 5.15 with a C++17 compiler is also supported.
2. Open `desktop/CMakeLists.txt` in Qt Creator.
3. Select the matching Desktop kit and configure the project.
4. Build and Run `CaroArena`.

Qt is a C++ GUI library; compiling this project as a single console `.cpp` file in a compiler without Qt will not work.

## Command-line build

Run in a terminal configured for the chosen Qt kit, or supply its paths explicitly:

```powershell
cmake -S desktop -B desktop/build -G Ninja `
  -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/mingw_64" `
  -DCMAKE_CXX_COMPILER="C:/Qt/Tools/mingw1310_64/bin/g++.exe" `
  -DCMAKE_BUILD_TYPE=Release
cmake --build desktop/build
ctest --test-dir desktop/build --output-on-failure
./desktop/build/CaroArena.exe
```

The paths above are examples; use the paths/version installed on your machine. The compiler architecture and version must match the Qt kit. Add the matching Qt `bin` and MinGW `bin` directories to the current terminal's PATH before running a development build.

To prepare a portable Windows app, run from that same Qt kit terminal:

```powershell
New-Item -ItemType Directory -Force desktop/build/package
Copy-Item desktop/build/CaroArena.exe desktop/build/package/
windeployqt --release --compiler-runtime desktop/build/package/CaroArena.exe
```

Distribute the entire package folder, including the `platforms` directory and DLLs. Follow the Qt and compiler runtime license requirements when distributing those dependencies.

## AI integration for the team

UI implementation: `src/window.cpp`. Rules: `src/game.h`. Adapter contract: `src/ai.h`. Register algorithms in `src/main.cpp`, after constructing `window`:

```cpp
window.registerAI("minimax", [](const caro::AiRequest &request) {
    // Call the team's C++ MiniMax implementation here.
    // Example signature only; teamMinimax is supplied by your group.
    return teamMinimax(request);
});
```

Supported provider names are `random`, `minimax`, and `mcts`. Register each separately. No fallback random moves are generated by the interface.

Input is a **copy** of the 9×9 `std::array` board, with `'\0'` for an empty cell, `'X'` / `'O'` for occupied cells. The request also contains the current player, shared parameters and a cancellation flag.

```cpp
caro::AiResponse chooseMove(const caro::AiRequest &request) {
    // Run the team's algorithm, periodically checking this flag:
    if (request.cancelled->load()) return {};
    caro::AiResponse response;
    response.cell = {row, col}; // zero-based; {4, 4} is E5
    response.depth = actualDepth;   // optional
    response.nodes = visitedNodes;  // optional
    return response;
}
```

The identifiers `row`, `col`, `actualDepth`, `visitedNodes` and `teamMinimax` in these snippets represent values/functions supplied by the team's implementation, not built-in example algorithms.

Providers run on Qt's thread pool: **do not access widgets or call `registerAI()` from the provider**. Register on the GUI thread before showing the window. Check `request.cancelled` regularly; C++ cannot forcibly stop an arbitrary algorithm. A provider that ignores cancellation can delay application shutdown. Returned moves from canceled turns are discarded; invalid moves and exceptions become visible errors. Restart or undo to retry after a provider error; AI-vs-AI can also pause/resume.

The UI measures elapsed provider time itself. Optional depth/nodes must be actual measured statistics. Unknown values display a dash. The game clock measures wall time, including pauses, and stops when the game ends. The restart prompt suspends AI moves while asking for confirmation.

JSON saves a snapshot of the current board, applied configuration, move history, available metrics and result. It is not a substitute for the assignment's batch experiments or charts.

## Rule tests without Qt

These compile with any C++17 compiler:

```powershell
cmake -S desktop -B desktop/build-tests -DCARO_BUILD_GUI=OFF
cmake --build desktop/build-tests
ctest --test-dir desktop/build-tests --output-on-failure
```

Tests cover the four win directions, blocked ends, six-in-a-row, illegal moves, turn order, undo after a win, draw detection and rejecting moves after game over. They do not verify GUI appearance or the group's AI.
